# Settings inventory (round 3)

Design only. Every control that the v5 Settings screen shows, built from the code (`SettingsRepository` Keys, `HydrationPrefs`, `FoodDataPrefs`, `OnboardingRepository`, `UserProfile` Advanced, `AiFeature` / `AiTask` / `AiPrivacy`, `HealthConnectManager.TYPES`, `ApiKeyStore`, `SyncSection`, `BackupScreen`, `HelpScreen`) and cross-checked with `IA-v5.md` section 4a. It is the data behind the settings pages in `design/mockup-v5/option-*.html`, generated by `design/mockup-v5/build/gen-inventory.js` from `design/mockup-v5/build/settings-data.js`.

Rules that apply to every row: use screens hold no configuration; one home per setting; keys live in the encrypted key store; "new" marks a control that does not exist in the app today.

## Removed outright

Remote backup destination (protocol, host, port, user, password, private key), backup schedule, backup passphrase and the server-identity trust dialogs (`backup_destination_json`, `backup_schedule`), per `FEEDBACK-R2.md`. `MIGRATION_2_3` need not touch them.

## Changes from IA v5 section 4a

* Split out **Health Connect** (15 per-type switches) and **Food database** (5 controls) into their own groups, and gathered every key into **API keys**; v5 had them inside "Data sources", "Videos" and "AI". This takes the groups from 9 to 12.
* **About and help** is now a group. The user asked for about, credits, privacy and help to be in Settings. IA v5 kept replay-tour in You > Help; it now has one home, here.
* Added the per-feature "uses a day" fields (7), the per-task model pickers (5), the AI privacy radio (zero retention, no data collection, any provider), and the three scheduled helpers, all from `AiSettingsScreen` and `AiUsageCards`.
* Added **Food portions (g / oz)** (fixes B2: photo estimate always used grams) and **Eat out nearby: search radius** (Swap).
* Goal weight and rate leave Settings, as IA v5 decided; Settings > Nutrition keeps the target controls.
